Empty batch (after admission) returns the input reference, `committed []`, no `seq` change. A `seq` past `MAX_SAFE_INTEGER` throws `RangeError`. Never throws for batch/option content.

- Control (`control.ts`): `control_set` validates phase in `def.control.phases`, every `active_seats` entry and `pointer.seat` an existing roster seat (`direction` is shape-validated), pointer NAME is not checked against `pointerNames` (D-024); only named fields are written (`control` replaced; untouched members keep references). `control_advance`: `mode` present -> `MALFORMED_ACTION` (`.mode`); start = `activeSeats[0]` or `pointers[name]` (empty / missing / not in `turnOrder` -> `MALFORMED_ACTION`); the lap of `seated` seats after the start in `direction` (start last) is built and `lap[(steps-1) mod len]` chosen (huge `steps` is O(n)); no seated seat -> `MALFORMED_ACTION`. Committed action is the input action.
- Zones (`zones.ts`, `zone-ids.ts`): `zone_create` check order: unknown template, owner rule (`none` takes no owner; others need an existing seat (roster), declared team or rostered player), `zone_id` (if given) equals derived, id length <= 128, collision with an existing zone (all `MALFORMED_ACTION`), then `ZONE_LIMIT` when the LIVE zones of the template (all owners) already reach `maxInstances` (D-022). - Grants (`grants.ts`): validation order target, keys, grantee, scope (paths `.target .keys .grantee .scope`), then `grant_id` (if given must equal derived). Id `grant/<ctx.seq>/<ctx.position>` (`position` = index in the committed primitive list). Stored `{target, keys, grantee, scope}` as given; logs `{...action, grant_id}`. Target shapes must have exactly the listed keys; `top` needs an ordered zone; `until_seq.n` safe integer >= `ctx.seq`. Grantee: declared seat id, `all_seated`, or `team:<declared team>`. `revoke_view`: unknown id -> `MALFORMED_ACTION` (`.grant_id`).
- Delegations (`roster.ts`): seat must exist in `state.roster.seats`; `(seat, principal)` identity; `delegate` appends `{seat, principal, scope?, boundary?}`, duplicate -> `MALFORMED_ACTION`; `revoke_delegation` removes the pair, absent -> `MALFORMED_ACTION`. Principal length/surrogates are shape-validated.
- `ratioRound(x: bigint, ratio: Ratio, mode: RoundingMode): bigint` (`core/session`, `session/ratio.ts`): `round(x*num/den)` exact; `floor` toward -inf, `half_up` ties away from zero, `half_even` ties to even quotient; `den <= 0n` throws `RangeError` (precondition; `validateAction` already rejects it). `scale` never enters.
- Counter semantics: `counter_adjust` -> `value += applied` (`delta` or `ratioRound(delta, ratio, decl.rounding)`); `counter_transfer` -> net change per counter id computed first (`from -= amount`, `to += credited`, `remainder_to += amount - credited`; aliasing sums), bounds checked on the final values in order from/to/remainder_to, written only if all pass. Mode = source counter's. Errors: unknown/derived counter, negative amount, `ratio` with no declared mode (path `.ratio`), non-zero remainder without `remainder_to` (path `.remainder_to`) -> `MALFORMED_ACTION`; bound violation -> `COUNTER_BOUNDS` (detail names counter and bounds; `actionIndex` = input index). Negative remainder (`credited > amount`) is applied as-is (D-020).
- `checkConservation(def, base, final, committed)` (stage 4, only runs for a non-empty committed list): per group, `sum(final) == sum(base) + sum(applied of counter_adjust on members with supplyRole)`, else `COUNTER_BOUNDS` naming the group; `actionIndex` = max `inputIndex` of entries whose net change on a member is non-zero. Transfers count only toward the sum equation through their net changes (never as supply). Mint/burn direction is not enforced (D-021). Groups are checked in definition order, first violation wins.

## Known gaps
- `docs/canonical-json-profile.md` and its test (VC-066): iteration 13. SPI/ports types: 11.
- Macro expansion details (D-028..D-030): unordered `to_zone` ignores the macro's `to_position`; `reset_to_zone` rejects duplicate zones; `EMPTY_ZONE` carries path `$[i].count`.
- Reducer limits (iteration 9): game reducers cannot change cards, zones, counters or control by construction (they return only their partition); the invariant re-check is defence in depth plus the roster-seat references. No engine-side defaults for roster `join`/`leave` (no counter/zone instantiation, spec out of scope). Gate quorum/timeout/nested gates are out of P1. A roster reducer's output is a detached copy, so unchanged seat entries are not `===` to the input's (the `roster` member itself is replaced).
- VC-022/090-092 properties, VC-067 golden stream, VC-100 perf: 12.
- No batch-length cap in P1 (plan-level decision); payload depth is capped at 64, array lengths and string sizes are not.
- No canonical schema for actions in P1: VC-025 compares committed actions with a bigint-aware `JSON.stringify` (`actionsText`).
- `apply` does not check that its input state is frozen (a programmer error). The SPI (iteration 11) re-exports `Reducer<S>` from `session/reducer.ts`.
- Definition gaps: duplicate zone-template names, duplicate meta schema ids, duplicate conservation group ids and `maxInstances` sanity are NOT checked (not in KFR-101); no definition `id`/content identity field (P2).
- State gaps (D-010): initial card orientation `face_down`, initial metadata `{}`, initial `meta` partitions `{}`; per-card metadata strictness is enforced by `apply` (`set_metadata`), the digest schema is the union of declared fields. Keyed records with ids like `__proto__` are handled by own-key helpers (D-018): code reading records by caller ids must use `getOwn`/`hasOwn`.
- `GameRejection` shape (`code` + optional `detail`) is a plan-level choice (D-001); revisit in iteration 11/12 if the SPI needs more.
